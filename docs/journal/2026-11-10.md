# 2026-11-10: URL checker script

## What I did
- Learned the basics of the Python `requests` library before building.
- Set up the repo (`Uptime_Monitor_Platform`) with a `develop` branch and only the folders I actually need, adding the rest as I go.
- Created a virtual environment (`.venv`) and pinned dependencies in `app/requirements.txt`.
- Wrote `app/checker.py`: it reads URLs from `urls.txt`, checks each one, and prints UP or DOWN with the status code and response time.

Example output:

```
UP   200                 0.155s  https://www.google.com/
UP   200                 0.177s  https://www.github.com/
DOWN ConnectionError     0.044s  https://www.thisdoesnotexist.rp/
```

## What went wrong
- **Double requests.** My first `main()` called `check_url()` twice per URL to print the status and the time. That doubled the traffic, and the two values came from different requests. Fixed by calling it once and unpacking the result.
- **A set instead of a value.** I returned `{status_code, error_name}` for HTTP errors. Curly braces make a set, which has no order, so the output could change between runs. Fixed by returning only the status code.
- **Lost status codes.** At first an HTTP error returned just "HTTPError", so a 404 and a 503 looked the same. Fixed by reading the code from the exception's response.
- **Timing in the wrong place.** I moved the timing into `main()`, which would have forced me to copy it into the worker later. Moved it back inside `check_url()`.
- **Branch not on GitHub.** `develop` only existed locally until I pushed it with `git push -u origin develop`.

## What I learned
- Wrapping requests in `try/except RequestException` means a dead site gets reported instead of crashing the script.
- A DNS failure returns almost immediately, while a site that never answers would wait for the 5-second timeout.
- `ConnectionError` can't tell "domain doesn't exist" from "server unreachable".
- `Path(__file__).parent` makes the path to `urls.txt` independent of the folder I run the script from, which will matter inside a container.
- `pip freeze` lists the dependencies of `requests` too, which is fine for reproducible builds.

## Decisions
- **What counts as "up":** any response below status 400 (via `raise_for_status()`).
- **Timeout:** 5 seconds per request.
- **Pinned all dependencies**, including the ones `requests` pulls in, so Docker and CI will install the same versions.
