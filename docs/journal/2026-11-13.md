# 2026-11-13: FastAPI and Postgres

Progress since the last entry (the URL checker script).

## What I did
- Built the FastAPI app with a health endpoint and endpoints to add, list and delete monitors.
- Ran PostgreSQL 16 in Docker Compose with a named volume, and kept credentials in a git-ignored `.env` (with a committed `.env.example`).
- Added `app/db.py` (psycopg) with two tables, `monitors` and `checks`, linked by a foreign key with `ON DELETE CASCADE`.
- Replaced the in-memory list with Postgres, so monitors survive a server restart.
- Connected `checker.py` to the API: one endpoint runs a check and saves the result, another returns a monitor's history.
- Normalised URLs on input, so `google.com`, `www.google.com`, `https:www.google.com` and `https://www.google.com/` all work.
- Wrote pytest tests for the endpoints, including parametrized tests for the URL formats.

## What went wrong
- **FastAPI course felt like too much.** I stopped watching and built the smallest endpoint instead, which made the concepts click.
- **Venv problems in WSL.** `pip` hit `externally-managed-environment` because the venv wasn't active, and `ensurepip is not available` because Ubuntu lacks venv support by default (fix: `sudo apt install python3.12-venv`). I also looked in `Scripts/` for `activate`, but a Linux venv uses `bin/`.
- **Divergent branches on push.** Local and remote `develop` each had commits the other lacked. Fixed with `git pull --no-rebase`, with no force push.
- **Committed as root.** I ran git with `sudo`, so the commit used the wrong identity and could leave root-owned files. I undid it with `git reset HEAD~1`, which keeps the changes in the working folder, then recommitted as my normal user. Lesson: never use `sudo` with git.
- **`__pycache__` committed by mistake.** Fixed with a `.gitignore` entry and `git rm -r --cached`.
- **Tests broke after the move to Postgres.** They still imported the old in-memory list (`ImportError`). I replaced the cleanup fixture with `TRUNCATE ... RESTART IDENTITY CASCADE`.
- **`MissingSchema` in the history.** The API had accepted a URL with no `https://`, which the checker correctly refused. The real fix was validating and normalising input when it is added.

## What I learned
- A FastAPI endpoint is a Python function attached to a URL, and invalid input gets a 422 automatically.
- A test fixture with `autouse=True` keeps tests independent.
- Pass SQL values as parameters (`%s`), never through f-strings, to avoid SQL injection.
- `RETURNING` gives back the row just inserted or deleted, which also shows whether a delete matched anything.

## Decisions
- **Postgres 16, pinned**, to match what I'll run on AWS RDS later.
- **Default to `https://`** when no scheme is typed.
- **`google.com` and `www.google.com` stay separate**, since merging them would be guessing.
- **Deleting a monitor deletes its history**, permanently.
- **Tests use my local database for now.** A separate test database is a later improvement.
